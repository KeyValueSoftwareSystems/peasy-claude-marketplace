PEASY-XXX · itsme and Google login
Peasy / Epics / PEASY-XXX

Let users log in with itsme and Google

Summary

Peasy users can only log in with email and password today. This epic adds itsme and Google login on peasy.be, links them automatically to existing accounts with a verified matching email, and pre-fills name, address and date of birth from itsme so insurance and mortgage quotes need less typing.

Context

  • Current behaviour: Login and Register with email + password and "Forgot password". No social login, no itsme.
  • itsme is Belgium's digital identity app: 8M+ users (March 2026), eIDAS-notified at assurance level high. Belgian users know it from banking and government services.
  • Insurance and mortgage flows ask for name, address and date of birth; itsme can supply these verified.
  • Personal data controller is Verzekeringen NV; data is shared within the group (Hypotheekwinkel BV, e-Contract BV, Horizon Holdco NV).

Scope

In scope

  • Sign up / log in with itsme and Google on peasy.be web (desktop + mobile web, NL + FR)
  • Auto-link to an existing account when the provider returns a verified matching email
  • itsme pre-fill: name, address, date of birth; itsme data overwrites old data and the changes are shown
  • Privacy notice for itsme data
  • Account page "Inlogmethodes": view, link, unlink (if another method remains)

Out of scope

  • Apple, Microsoft, Facebook login
  • Mobile app
  • Hypotheek.winkel, Verzekeringen.be, Aanbieders.be, Meilleurtaux brands
  • Removing email + password
  • itsme e-signature for contracts

User stories

S1 Sign up and log in with itsme

5 pts

As a Belgian user, I want to log in with itsme, so that I don't need to remember another password.

Given I'm on the login or register page When I choose "Inloggen met itsme" and approve in the itsme app Then I'm logged in, or a new account is created if none matches.
Given I cancel in the itsme app When I return to Peasy Then I see the error banner "Inloggen met itsme is mislukt of geannuleerd…" and no account is created.
Given itsme is unavailable When I try to log in Then I see the same error banner and Google and email login stay usable.
Given itsme returns my national register number When my account is saved Then the number is not stored.

S2 Sign up and log in with Google

3 pts

As a user, I want to log in with my Google account, so that signing up takes one click.

Given I choose "Inloggen met Google" When Google returns a verified email Then I'm logged in, or a new account is created if none matches.
Given I close the Google window or deny access When I return to Peasy Then I see an error banner and stay on the login page.
Given Google returns an email that is not verified When I log in Then no account is created or linked and I'm asked to use another method.

S3 Link SSO to my existing account

5 pts

As an existing email + password user, I want itsme or Google linked to my account automatically, so that I keep my comparisons and contracts.

Given the provider returns a verified email matching an existing Peasy account When I log in Then the provider is linked to that account and I see "We hebben itsme gekoppeld aan je account …".
Given a provider was linked automatically When linking succeeds Then I receive a notification email so I can react if it wasn't me.
Given the provider email is unverified or missing (itsme may not return one) When I log in Then no automatic link happens and a separate account is not created silently. (Behaviour TBD, see open question 2)
Given my account is linked When I log in with email + password later Then that still works.

S4 Pre-fill my profile from itsme

3 pts

As a user requesting an insurance or mortgage quote, I want my details filled from itsme, so that I type less and avoid mistakes.

Given I log in with itsme for the first time When I land on "Klopt dit?" Then I see name, date of birth and address from itsme and a short notice of what we store and why, with a link to the privacy policy.
Given my saved profile has a different address or empty date of birth When itsme returns data Then itsme values overwrite the old ones and each changed field shows the old value struck through with "Gewijzigd" or "Nieuw".
Given I choose "Annuleren" on the confirmation screen When I leave Then no itsme data is saved and I'm not logged in. (Assumption)
Given itsme returns no address When the screen loads Then the address row is hidden and my existing address is kept.

S5 Manage my login methods

3 pts

As a logged-in user, I want to see, link and unlink my login methods, so that I stay in control of my account.

Given I open Mijn account › Inlogmethodes When the page loads Then I see itsme, Google and E-mail en wachtwoord, each with status "Gekoppeld" or "Niet gekoppeld".
Given a method is not linked When I choose "Koppelen" and complete the provider flow Then it shows as "Gekoppeld" with a success banner.
Given I have two or more methods When I unlink one Then it's removed and I get a confirmation email.
Given I have only one method left When I view it Then "Ontkoppelen" is disabled with the hint "Koppel eerst een andere methode…".

Non-functional

  • Privacy (GDPR): lawful basis for storing itsme data TBD (contract vs consent); never store the national register number; log the itsme data source and timestamp; update privacy policy and record of processing (controller Verzekeringen NV). Retention follows existing rule for service users (5 years) unless Legal decides otherwise. [Legal text: todo]
  • Security: OpenID Connect with PKCE, state and nonce checks; only auto-link on email_verified = true; notification email on every new link; existing session length and logout unchanged.
  • Accessibility: WCAG 2.2 AA; provider buttons keyboard-reachable with visible focus-ring; error banner announced (role="alert"); disabled unlink explained in text, not colour alone.
  • Performance: no extra load on the login page beyond provider buttons; provider SDKs loaded on click if possible.
  • Analytics: login_method_selected, login_success, login_failed (with reason: cancelled / provider_error / unverified_email), account_linked, account_unlinked, prefill_confirmed, prefill_cancelled. Success target: TBD.
  • Rollout: behind a feature flag. % rollout TBD.

Dependencies

  • itsme partner contract, scopes and test environment (via itsme or an approved broker)
  • Google Cloud OAuth client and consent screen verification
  • Official itsme and Google button assets and brand guidelines
  • Legal review of privacy notice and lawful basis (NL + FR)
  • Auth service supporting multiple identities per user
  • Email template for "new login method linked / unlinked"

Assumptions

  • Assumption: Google's email_verified claim is trusted for auto-linking.
  • Assumption: Peasy has (or will build) a "Mijn account" area where Inlogmethodes can live.
  • Assumption: Cancelling the itsme confirmation screen aborts login rather than logging in without pre-fill.
  • Assumption: The current auth stack can add OIDC providers without a rewrite.

Open questions

  1. Which itsme scopes and contract do we need (name, address, DOB, email?), and what does it cost? Owner: Tech + Legal
  2. itsme may not return a verified email. How do we link an itsme login to an existing email account then (ask for password, or email verification)? Owner: Product + Tech
  3. Lawful basis for storing itsme data: contract or consent? Does the notice need an explicit opt-in? Owner: Legal
  4. Does "itsme wins" need user confirmation for address changes that affect active insurance contracts? Owner: Product + Legal
  5. What does a user see in "Mijn account" today (quotes, contracts, documents)? Verify with Peasy. Owner: Product
  6. Should this login later extend to Hypotheek.winkel, Verzekeringen.be and Meilleurtaux Belgium? Affects identity architecture now. Owner: Product
  7. Success metric and target (e.g. share of logins via SSO, form completion time). Owner: Product
  8. Final French copy. Owner: Content
